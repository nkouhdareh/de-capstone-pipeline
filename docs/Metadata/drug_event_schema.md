# drug/event — actual data schema (Spark-inferred)

The real structure Spark inferred from the ingested **bronze `drug_event`** data
(2,687,675 records, 2023–2024). This confirms `field_dictionary.md` against the data we
actually downloaded. Regenerate any time in the notebook with `df.printSchema()`.

## Key points for cleaning (Silver)

- **Every field is `string`** — dates (`receivedate`), numbers, and codes (`serious`,
  `patientsex`) are all stored as strings. The Silver layer casts them (e.g. `receivedate` → date).
- **Nested arrays to flatten:** `patient.drug[]` (with an `openfda` struct inside) and
  `patient.reaction[]`. Exploding these to one row per **(report, drug, reaction)** is the core
  Silver step (#4/#5).
- **Matches the field dictionary** ✅ — no surprise fields.
- **Note:** `reportduplicate` came out as `string` here, though the openFDA spec lists it as an
  object (`duplicatenumb`, `duplicatesource`). That's a Spark schema-inference quirk (the field
  is rarely populated) — worth remembering if you ever use it.
